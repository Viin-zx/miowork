# 隐藏服务商菜单并通过配置文件预置默认服务商

## Context

用户在做一个分发给最终用户的定制版 DeepChat，希望：
1. 最终用户在设置中心看不到"服务商设置"菜单（避免误改预置配置）。
2. 通过一份外部 JSON 配置文件预置默认服务商，应用首次启动即注入，开箱即用。
3. 本次先预置一个 NewAPI 中转站：`https://newapi.zrshuiwu.com/v1` + 给定 apiKey，协议用 `openai-completions`。

复用项目现有机制：`hiddenInSidebar` 字段（dashboard/mcp/ocr 等已用）、`DEFAULT_PROVIDERS` 注入逻辑（`ProviderSettings` constructor 已实现"合并新 provider"）、`resources/*.json` 静态配置约定（参考 `runtime-versions.json` 的 import 模式）。

## 改动点

### 1. 隐藏"服务商设置"菜单项

文件：`src/shared/settingsNavigation.ts`（第 128-136 行 `settings-provider` 项）

在 `settings-provider` 项中加一行 `hiddenInSidebar: true`。语义与现有 `settings-dashboard`/`settings-mcp` 一致：左侧菜单不显示，但路由 `settings-provider` 和组件 `ModelProviderSettings.vue` 保留，直链（如 `deepchat://settings/provider`）仍可访问。chat 页面的模型选择器不受影响。

### 2. 新建配置文件

文件：`resources/default-providers.json`（新建）

数组格式（支持未来追加多个），本次填入 zrshuiwu 一项。字段对齐 `LLM_PROVIDER_BASE`（`src/shared/types/provider.ts` L109-126）：

```json
[
  {
    "id": "zrshuiwu",
    "name": "ZRShuiwu",
    "apiType": "openai-completions",
    "apiKey": "sk-hXhSQhXpgsXmBRTGNn0jUsBaIj0SIovHQ9wVwEyGkE9z1zKs",
    "baseUrl": "https://newapi.zrshuiwu.com/v1",
    "enable": true,
    "websites": {
      "official": "https://newapi.zrshuiwu.com",
      "apiKey": "",
      "docs": "",
      "models": "",
      "defaultBaseUrl": "https://newapi.zrshuiwu.com/v1"
    }
  }
]
```

不预置 `models` 列表：NewAPI 中转支持 `/v1/models` 拉取，首次在 chat 页选模型时应用会自动调用 `getModelList` 刷新。

### 3. 读取配置并合并到默认 providers

文件：`src/main/provider/settings.ts`（第 25 行附近 import 区，第 73-86 行 `defaultProviders` 定义处）

- 顶部新增：`import defaultProvidersConfig from '../../../resources/default-providers.json'`
- `defaultProviders` 定义改为：先 `DEFAULT_PROVIDERS.map(...)`（保持现有映射），再 `...defaultProvidersConfig`（配置文件里的 provider 直接展开，字段已对齐 `LLM_PROVIDER_BASE`，不需要再次 map）。
- 不动 constructor 第 407-415 行的合并逻辑：它已经按 `id` 把 `defaultProviders` 中新 provider 合并到 `existingProviders`，复用即可。

合并语义（重要，需在 PR 说明）：
- 首次启动：`zrshuiwu` 不在 existingProviders 中 → 自动注入并 enable。
- 用户在 UI 删除 `zrshuiwu` 后下次启动：因 `defaultProviders` 仍含该项，会被再次注入。这是"固化默认"的预期行为，符合定制分发场景。
- 如未来希望"用户主动删除后不再注入"，可加 dismissed 标记，本次不做。

### 4. TypeScript JSON 模块声明（如需）

`tsconfig.json` 已有 `resolveJsonModule`（项目里 `runtime-versions.json` 能直接 import 说明已开启），无需新增配置。

## 边界与提示

- **apiKey 明文** 会进 git 仓库与发布包。用户给的就是明文，符合定制分发意图。若不希望 key 进 git，可把 `default-providers.json` 加入 `.gitignore`，但那样打包时不会包含、定制配置失效——本次按用户意图保留入库。
- 不改 i18n：菜单隐藏后 `routes.json` 中的 `settings-provider` 文案不再展示，保留 key 无副作用。
- 不预置模型列表：首次使用时由应用自动拉取，避免硬编码模型 ID 过期。
