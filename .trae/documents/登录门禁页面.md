# 登录门禁：登录页 + 聊天/设置页面放行控制

## Context

定制版 DeepChat 需要登录门禁：应用启动后先显示登录页，凭默认账号 `admin`/`admin123` 登录成功后才能使用聊天页面和设置（管理）页面。两个窗口共享同一登录态（主进程内存），应用重启后需重新登录。账号密码本期硬编码在主进程 auth 模块常量中（"先默认"，后续可抽配置文件）。

**探索确认的关键事实**（均已亲自核实）：
- IPC 桥是通用的：`src/preload/createBridge.ts` 按 `DEEPCHAT_ROUTE_CATALOG` 契约校验并转发 `window.deepchat.invoke(routeName, input)` → **新增路由无需改 preload**。
- 路由契约注册表：`src/shared/contracts/routes.ts`（import 各 routes 文件 → `DEEPCHAT_ROUTE_CATALOG_PART_N` → `export *`）。
- 主进程 handler 挂载：`src/main/app/composition.ts` L3046-3093，`createRouteDispatcher({ routeMaps: [...] })` + `registerDeepchatRoutes(ipcMain, ...)`。
- 渲染层 client 模式：`src/renderer/api/*Client.ts`（如 ConfigClient.ts），包装 route contract 调用；`@api/*` 别名指向 `src/renderer/api/*`，两个 renderer（chat/settings）共用。
- 聊天窗口：`App.vue` 仅渲染 `ChatMainApp.vue`（`src/renderer/src/apps/chat-main/ChatMainApp.vue`），内部 L544 `<RouterView v-if="isStartupRouteReady" />`，整体 UI（AppBar/侧栏/RouterView）都在其模板内 → 在 ChatMainApp 模板根部做条件渲染即可整窗门禁。
- 设置窗口：`src/renderer/settings/App.vue`（sidebar + RouterView）；其 L719 `notifySettingsReady()` 在 onMounted 中调用（主窗口显示依赖它）→ **gate 必须只做模板条件渲染，script/onMounted 照常运行**，否则设置窗口永远不显示。
- settings renderer 已有从 chat renderer 相对导入的先例（`settings/main.ts` L10 `import { preloadIcons } from '../src/lib/iconLoader'`）→ LoginPage 组件可共用。
- i18n：两个 renderer 共用 `src/renderer/src/i18n/bootstrap.ts`（`createRendererI18n`），fallback locale 兜底；每语言目录有 `index.ts` 聚合 json。
- 已存在 `windowStartGuidedOnboardingRoute` 等 window 路由模式可参考（`src/main/desktop/routes.ts`）。

## 改动点

### 1. 主进程 auth 模块（新建）

**`src/main/auth/authService.ts`**
- 常量：`DEFAULT_ADMIN_USERNAME = 'admin'`、`DEFAULT_ADMIN_PASSWORD = 'admin123'`。
- `class AuthService`：内存态 `private authenticated = false`；方法 `isAuthenticated(): boolean`、`login(username, password): boolean`（常量比对，成功置 true）。
- 无持久化（重启即失效，符合"每次启动都需登录"）。

**`src/main/auth/routes.ts`**
- `createAuthRoutes(auth: AuthService): DeepchatRouteMap`，用 `createRouteMap([...])`（同 `src/main/desktop/routes.ts` 模式）。

### 2. IPC 契约（新建 + 注册）

**`src/shared/contracts/routes/auth.routes.ts`**（新建，仿 `system.routes.ts`）
- `authGetStatusRoute`：input `{}` → output `{ authenticated: boolean }`
- `authLoginRoute`：input `{ username: string, password: string }` → output `{ ok: boolean }`（不区分"用户不存在/密码错误"）

**`src/shared/contracts/routes.ts`**（修改）
- import 两个 route；加入 `DEEPCHAT_ROUTE_CATALOG_PART_5`（体量小）；追加 `export * from './routes/auth.routes'`。

### 3. 主进程接线

**`src/main/app/composition.ts`**（修改）
- 创建 `authService = new AuthService()`；`const authRoutes = createAuthRoutes(authService)`；`authRoutes` 加入 L3050 `routeMaps` 数组。

### 4. 渲染层 client（新建）

**`src/renderer/api/AuthClient.ts`**
- `createAuthClient()`（仿现有 Client 文件模式）：`getStatus()`、`login(username, password)`。
- 若 `src/renderer/api/index.ts` 有统一导出清单则追加。

### 5. 登录页组件（新建，两个 renderer 共用）

**`src/renderer/src/pages/LoginPage.vue`**
- 风格参考 `src/renderer/src/pages/WelcomePage.vue`：全屏居中卡片、Logo、标题、描述、表单区；用 shadcn-vue 的 Input/Button/Label + Tailwind token（`bg-card`/`text-primary` 等）+ `Icon`（iconify）。
- 逻辑：`<script setup>` + `useI18n`；username/password refs；submit 调 `createAuthClient().login()`；失败显示错误文案（shake 或红色提示）；成功 `emit('authenticated')`。
- 文案全部走 i18n（`login.*` 键）。

### 6. 聊天窗口门禁

**`src/renderer/src/apps/chat-main/ChatMainApp.vue`**（修改）
- setup：`authStatus = ref<'checking' | 'unauthenticated' | 'authenticated'>('checking')`，同步发起 `getStatus()` 更新。
- 模板根部三分支：
  - `checking` → 空背景 div（`bg-background`，避免闪现主 UI）
  - `unauthenticated` → `<LoginPage @authenticated="authStatus = 'authenticated'" />`
  - `authenticated` → 现有整套 UI（原模板整体包进此分支）
- script 的初始化逻辑（IPC runtime、store 等）不动，照常执行。

### 7. 设置窗口门禁

**`src/renderer/settings/App.vue`**（修改）
- 同样的三分支状态机；`unauthenticated` 时模板渲染 `<LoginPage ... />`（相对路径 `../src/pages/LoginPage.vue` 导入）。
- **L719 `notifySettingsReady()` 所在 onMounted 不受影响**（script 照跑，仅模板分支变化），保证设置窗口正常显示。

### 8. i18n 文案

- 新建 `src/renderer/src/i18n/zh-CN/login.json` 与 `en-US/login.json`：键 `login.title`、`login.description`、`login.username`、`login.password`、`login.submit`、`login.submitting`、`login.error`。
- 在这两个目录的 `index.ts` 注册 `login`；其余 18 种语言靠 fallback locale，不加文件。
- 运行 `pnpm i18n:types` 重新生成 `src/types/i18n.d.ts`。

## 验证

1. `pnpm i18n:types` → `pnpm typecheck` → `pnpm lint` → `pnpm format:check`
2. `pnpm dev` 手动验证：
   - 启动 → 聊天窗口显示登录页（居中卡片，风格与 WelcomePage 一致）

   - `admin`/`admin123` → 进入聊天界面
   - 打开设置窗口 → 直接进入（同进程登录态共享）；重启应用后再直接开设置 → 显示登录页

3. 测试：`test/renderer` 若有 App.vue/ChatMainApp 相关快照测试需跑一遍；不新增测试（UI 门禁，实现耦合度高，按仓库规范优先不加）。

## 边界说明

- 这是本地桌面应用的 UX 门禁，不是安全边界（渲染层代码本地可改）；主进程 `auth.login` 契约本身不做防爆破限制（可后续加延迟）。
- deeplink（如 `deepchat://settings/provider`）在未登录时打开设置窗口会先看到登录页，登录后落在设置概览页（deeplink 目标导航可能丢失）——可接受的次要 UX 代价，计划内不做队列重放。
- 悬浮窗/浏览器 overlay 等其他窗口不做门禁（超出本次"聊天和管理页面"范围）。
